# App Store creative assets

Create high-quality, production-ready static images for the App Store product page header and search results of an existing app. Use this skill when asked to create or refresh those assets; it does not cover ordinary in-app UI or screenshot sets.

## Understand the app and its visual identity

- Do not assume product page header or search artwork already exists. Start from whatever project or supplied materials are available: app icon or logo, asset-catalog colors, representative screens, in-app illustrations, product descriptions, and App Store metadata. Use existing App Store art as a reference only when it is present.
- Treat the app's actual assets and metadata as the source of truth. If some materials are unavailable, continue with the strongest available evidence; do not pause for a specific file or invent missing brand elements or product details.
- Review the app's purpose, strongest user benefit, visual language, and representative experience using project information, screens, or App Store metadata where available. If an app icon or logo exists, use its recognizable colors, shapes, and finish as the campaign anchor. It can be featured prominently in a logo-and-copy lockup; do not assume it must be small or replaced with a new illustration.
- Read named colors from the app's asset catalog when available, and use those values for the campaign palette. Do not guess brand colors from memory or approximate them when source color values exist.
- Base every depicted feature and claim on evidence in the app or its supplied metadata. Do not invent capabilities, awards, endorsements, prices, or availability.
- Make a simple composition with one clear focal idea. Prefer the app's established mark, typography, palette, and a short literal description over generic gradients, decorative clutter, device mockups, or piles of floating UI. Use interface imagery only when it supports the requested direction and makes the product clearer.
- A tagline is optional. Add one only when a concise, verifiable phrase makes the app's value clearer; it should complement the image, not narrate it. Treat a full app description as source material, not default on-image copy. Add supporting description or a feature list only when requested or when it clearly improves understanding and remains legible. Keep all included text accurate and localizable where appropriate.
- When the existing artwork is already a simple brand treatment built from the app logo and brand colors, refine that visual language instead of replacing it with generic AI-generated scenes or unrelated interface mockups. Use image generation only when it clearly serves the app's established identity or the user asks for illustrative artwork.
- For refreshes, inspect any existing creative asset before redesigning it and preserve the parts that are already working. If the user requests particular copy, use concise, verifiable wording that fits the composition.
- Prioritize legibility at the small sizes where App Store artwork appears. Use only the text needed to identify the app and convey its value; remove secondary feature lists when they compete with the logo, name, or tagline.
- For search results, make the app identity and core purpose understandable from the image alone at a glance. Include the app name and a plain-language description; a logo or abstract motif alone is not enough. Do not depend on nearby store metadata to explain the image.
- When header and search art are both requested, default to the same simple campaign lockup in both: app mark, app name, and the same short purpose line. Keep the composition, palette, typography, and message consistent; adjust scale or spacing only as needed for the different aspect ratios. Do not invent a separate search concept, feature showcase, or interface composition unless the user asks for one or the existing brand treatment cannot explain the app.
- Check both assets at a realistic mobile listing size, not only at full resolution. The logo and app name must be immediately legible; the purpose line should remain readable and explicit. If the copy or mark is too small, simplify and enlarge it before delivery.
- Keep the whole lockup centered and within a generous crop-safe area. For a vertical logo-and-copy lockup, put the mark above the app name and purpose line, with deliberate top and bottom padding. Make the logo and type large enough to use the available safe area while retaining that padding.
- For wide horizontal lockups, measure and center the complete visible group, including the mark, the text block, and the gap between them. Keep generous left and right margins; do not let the mark sit close to an edge just because the full canvas looks centered. Preview tighter horizontal crops at realistic display sizes, then move the whole group inward or reduce its width while preserving a deliberate mark-to-type gap.
- When a placement may be center-cropped, preview the actual tighter crop at realistic display size and check that the complete lockup, especially every word, retains breathing room inside it. Do not assume a centered composition is automatically crop-safe.
- When Apple supports multiple aspect ratios for a placement, consider exporting a matching variant for each relevant ratio instead of relying on one image to crop well everywhere. Keep the campaign consistent and adapt scale and spacing to each canvas. Confirm dimensions and formats against Apple’s current specifications.

## Compose for App Store placements

- Before rendering, consult Apple's current [asset best practices](https://developer.apple.com/app-store/asset-best-practices/) and [creative asset specifications](https://developer.apple.com/help/app-store-connect/reference/app-information/creative-assets-specifications). Follow current placement dimensions, formats, and file requirements; these can change.
- Keep the focal artwork and every word centered within the safe area, with generous breathing room on all sides. Assume outer portions may be cropped or obscured differently across devices and orientations. Check Apple's current templates and safe-area guidance; do not assume the full canvas is always visible.
- Center the complete visual group, including logo, app name, tagline, and description, as a composition. Check the actual rendered bounds of the group; centering only the logo or aligning text by its baseline can leave the overall design visibly off-center.
- Header and search art should read as one campaign. Preserve the same app mark, name, purpose line, typography, and palette across placements; adapt scale and spacing for their aspect ratios while keeping the core lockup intact.
- Use opaque artwork with no alpha channel or transparency for submitted images. Export in a format and at dimensions Apple currently accepts for each placement.
- When both placements are requested, provide both assets. If the user asks for a general package and Apple's current requirements support a universal asset, explain the applicable option and include it when useful.

## Produce and review the artwork

- Use the available image-generation or design tools for custom visual artwork only when it fits the inspected app and its established visual identity. When the existing campaign is logo-and-color-led, prefer precise code or graphics compositing to preserve that identity.
- For precise typography, use a graphics or code-based compositing step after generating the background/artwork when practical. Keep text short, optically centered, high contrast, and comfortably readable at reduced display size. Do not rely on image generation to spell required copy correctly without checking it.
- For Apple-platform apps, prefer the platform system typeface (San Francisco for Apple platforms) unless the app has an established brand typeface that should carry through. Set an intentional hierarchy: give the app name the strongest weight, and use a lighter regular or medium weight for the purpose line. Tune size, weight, tracking, and line spacing together; avoid relying on a single weight for every line or making supporting copy compete with the name. Review the typography at realistic listing size.
- Render the final files at the exact required dimensions. Inspect each full-size output, a realistic mobile-size preview, and a crop/safe-area preview. Refine any clipped, off-center, too-small, low-contrast, malformed, or visually noisy elements before delivery. Confirm that the search image still clearly identifies the app and its purpose at mobile size.
- Save deliverables in a clearly named output folder in the project, unless the user specifies another location. Avoid replacing existing artwork without checking it first. Summarize the files, dimensions, format, and any tagline used.

Apple's placement rules and examples are authoritative and may evolve; check the linked pages when creating assets rather than treating remembered pixel values as permanent.
